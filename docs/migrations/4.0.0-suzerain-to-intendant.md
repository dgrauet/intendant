# v4.0.0 — Project rename: `suzerain` → `intendant`

**Breaking change.** The project has been renamed from `suzerain` to `intendant`.
Every identifier exposed to users — CLI binary, Python package, configuration
filename, MCP server name, snapshot directory — changes in a single hop. There
is no compatibility shim; the old names are gone.

See [ADR-0008](../adr/0008-rename-suzerain-to-intendant.md) for the rationale
(the PyPI name `suzerain` is taken by an unrelated project).

## What changed

| Surface | Before | After |
|---|---|---|
| PyPI package | *(not published under this name)* | `intendant` |
| CLI binary | `suzerain` | `intendant` |
| Python import | `import suzerain` | `import intendant` |
| Config file | `.suzerain.toml` | `.intendant.toml` |
| Snapshot directory | `<root>/.suzerain/snapshots/` | `<root>/.intendant/snapshots/` |
| MCP server id | `suzerain` | `intendant` |
| Main dataclass | `SuzerainConfig` | `IntendantConfig` |

> The `suzerain` package on PyPI is an unrelated project. Do **not** install it
> expecting this tool — use `uv tool install intendant` instead.

## Rule IDs

**Unchanged.** Rule prefixes (`DG`, `PYTHON_*`, `NODE_*`, `RUST_*`, `GO_*`,
`SWIFT_*`, `CLAUDE_SKILL_*`) and the report schema version are preserved. Your
existing exemption keys keep working — you only have to move them to the new
file.

## Migration steps

For each governed repository:

### 1. Rename the configuration file

```bash
git mv .suzerain.toml .intendant.toml
```

The file format is unchanged. The top-level table is still `[intendant]`
(it was already `[intendant]` in suzerain 3.x — only the filename moves).

### 2. Reinstall the CLI

```bash
# If you had the old name installed somehow
uv tool uninstall suzerain 2>/dev/null || true

uv tool install intendant
```

Then verify:

```bash
intendant --version
intendant audit . --severity=required
```

### 3. Update CI workflows

Any reference to the old binary or config in `.github/workflows/*.yml`,
`Makefile`, scripts, or pre-commit hooks must be updated:

```diff
- run: uv tool install suzerain && suzerain audit .
+ run: uv tool install intendant && intendant audit .
```

```diff
- if: hashFiles('.suzerain.toml') != ''
+ if: hashFiles('.intendant.toml') != ''
```

### 4. Update MCP client configuration

If you registered the MCP server in Claude Code / Claude Desktop / Cursor:

```diff
 {
   "mcpServers": {
-    "suzerain": {
-      "command": "suzerain",
+    "intendant": {
+      "command": "intendant",
       "args": ["mcp"]
     }
   }
 }
```

Re-register the server in your MCP client after the change.

### 5. Update Python imports (if any)

Repos that imported the package programmatically (e.g., for custom rules or
tests):

```diff
- from suzerain.core.rule import Rule
+ from intendant.core.rule import Rule
```

```diff
- from suzerain.core.config import SuzerainConfig
+ from intendant.core.config import IntendantConfig
```

### 6. Drop the old snapshot directory

Existing portfolio snapshots are still readable, but they live at the wrong
path:

```bash
# Move existing snapshots if you want to keep history
git mv .suzerain .intendant 2>/dev/null || true

# Or start fresh
rm -rf .suzerain
intendant report <portfolio-root> --save-snapshot
```

## Quick portfolio-wide rename

If you govern multiple repos and want to migrate them all at once, this
one-liner handles the common cases per repo:

```bash
for repo in <list-of-repos>; do
  (
    cd "$repo" || exit
    [ -f .suzerain.toml ] && git mv .suzerain.toml .intendant.toml
    [ -d .suzerain ] && git mv .suzerain .intendant
    grep -rl --exclude-dir=.git 'suzerain' .github Makefile* scripts 2>/dev/null \
      | xargs -r sed -i '' 's/suzerain/intendant/g; s/Suzerain/Intendant/g'
  )
done
```

Review the diff before committing — the `sed` step is broad on purpose; manual
verification is faster than crafting a surgical regex.

## Backward compatibility

**None.** Intendant 4.0.0 does not read `.suzerain.toml`, does not expose a
`suzerain` binary, and does not preserve `import suzerain`. The single-hop
rename was deliberate (see ADR-0008): the old name had no users beyond a single
governed repo, so a deprecation window would have been pure overhead.
