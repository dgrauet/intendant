# 03 — CI

## Rules

### CI001 — CI workflow required

**Severity:** required · **Stacks:** *

A `.github/workflows/ci.yml` workflow must exist and run on
every PR targeting `main`. No PR without a green CI.

### CI002 — Minimum steps appropriate for the stack

**Severity:** required · **Stacks:** *

The CI workflow runs at minimum the steps appropriate for the stack:

- **python** (and any unrecognised stack): lint (`ruff check`), format
  (`ruff format`), type-check (`ty check` or `pyright`), and tests
  (`pytest` or `unittest`).
- **node**: lint (`eslint`, `biome`, or `npm run lint`), type-check
  (`tsc`, `typecheck`, or `pyright`), and tests (`vitest`, `jest`,
  `mocha`, `ava`, `bun test`, `npm test`). A separate format step is
  not required (often merged with lint via `eslint --fix` or `prettier`).
- **claude-skill**: a `suzerain audit` step in CI (the skill validates
  itself via the suzerain audit step).

### CI003 — Commit message validation

**Severity:** required · **Stacks:** * · **ADR:** [0004-conventional-commits-strict](../adr/0004-conventional-commits-strict.md)

A CI job validates that all commits in the PR follow Conventional
Commits (`cz check --rev-range origin/main..HEAD`).

### CI004 — Dependency caching

**Severity:** recommended · **Stacks:** *

The workflow caches dependency resolution artifacts
(uv cache, npm cache...) to reduce execution time. `astral-sh/setup-uv@v4`
does this automatically when `enable-cache: true`.
