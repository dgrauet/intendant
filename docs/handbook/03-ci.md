# 03 — CI

## Rules

### CI001 — CI workflow required

**Severity:** required · **Stacks:** *

A `.github/workflows/ci.yml` workflow must exist and run on
every PR targeting `main`. No PR without a green CI.

### PYTHON_CI001 — Python CI minimum steps

**Severity:** required · **Stacks:** python

The CI workflow must run the Python quality gate steps: lint (`ruff check`),
format (`ruff format`), type-check (`ty check` or `pyright`), and tests
(`pytest` or `unittest`).

### NODE_CI001 — Node CI minimum steps

**Severity:** required · **Stacks:** node

The CI workflow must run the Node quality gate steps: lint (`eslint`, `biome`,
or `npm run lint`), type-check (`tsc`, `typecheck`, or `pyright`), and tests
(`vitest`, `jest`, `mocha`, `ava`, `bun test`, `npm test`). A separate format
step is not required (often merged with lint via `eslint --fix` or `prettier`).

### CLAUDE_SKILL_CI001 — Claude Skill CI minimum steps

**Severity:** required · **Stacks:** claude-skill

The CI workflow must include a `suzerain audit` step. The skill validates
itself via the suzerain governance audit.

### CI003 — Commit message validation

**Severity:** required · **Stacks:** * · **ADR:** [0004-conventional-commits-strict](../adr/0004-conventional-commits-strict.md)

A CI job validates that all commits in the PR follow Conventional
Commits (`cz check --rev-range origin/main..HEAD`).

### CI004 — Dependency caching

**Severity:** recommended · **Stacks:** *

The workflow caches dependency resolution artifacts
(uv cache, npm cache...) to reduce execution time. `astral-sh/setup-uv@v4`
does this automatically when `enable-cache: true`.
