# 03 — CI

## Règles

### CI001 — Workflow CI obligatoire

**Severity:** required · **Stacks:** *

Un workflow `.github/workflows/ci.yml` doit exister et tourner sur
chaque PR vers `main`. Pas de PR sans CI verte.

### CI002 — Étapes minimales : lint + type + test

**Severity:** required · **Stacks:** *

Le workflow CI exécute au minimum, en cet ordre :
1. Lint (ruff côté Python).
2. Format check (ruff format --check côté Python).
3. Type check (`ty` côté Python — cf. ADR-0003).
4. Tests unitaires.

### CI003 — Validation des messages de commit

**Severity:** required · **Stacks:** * · **ADR:** [0004-conventional-commits-strict](../adr/0004-conventional-commits-strict.md)

Un job CI valide que tous les commits de la PR respectent Conventional
Commits (`cz check --rev-range origin/main..HEAD`).

### CI004 — Cache des dépendances

**Severity:** recommended · **Stacks:** *

Le workflow met en cache les artefacts de résolution de dépendances
(uv cache, npm cache...) pour réduire le temps d'exécution. `astral-sh/setup-uv@v4`
le fait automatiquement quand `enable-cache: true`.
